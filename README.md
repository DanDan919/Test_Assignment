# TestTask API

## Requirements

- Docker Desktop or Docker Engine with Compose
- .NET 10 SDK for local build/test commands

## Запуск

```text
docker compose up --build
```

API слушает `http://localhost:8090`.

Swagger доступен по адресу `http://localhost:8090/api/swagger`.

POST endpoint: `http://localhost:8090/api/process`.

URLs:

```text
API:     http://localhost:8090
Swagger: http://localhost:8090/api/swagger
pgAdmin: http://localhost:8080
```

## API pipeline

`POST /api/process` выполняет validation, Base64/UTF-8 decoding, AngleSharp
HTML parsing, CSS selector и attribute extraction, compiled email Regex,
AES-256 ECB decryption и сохранение элементов через Dapper в PostgreSQL.

При старте API-контейнер выполняет из mounted source directory:

```text
dotnet restore
dotnet build
dotnet run
```

## Compose services

- `api` — .NET 10 SDK container; исходники монтируются из `./src` в `/workspace/src`;
- `postgres` — официальный `postgres:18`;
- `pgadmin` — официальный `dpage/pgadmin4:9.18`.

PostgreSQL использует:

```text
database: testtask
user:     testtask
password: testtask
host:     postgres
port:     5432
```

Connection string передаётся через `ConnectionStrings__Postgres`, а не зашивается в C#:

```text
Host=postgres;Port=5432;Database=testtask;Username=testtask;Password=testtask
```

Для PostgreSQL 18 используется named volume `postgres_data`, смонтированный в `/var/lib/postgresql`.

## Database initialization

При старте API `DatabaseInitializer` создаёт таблицу автоматически:

```sql
CREATE TABLE IF NOT EXISTS elements
(
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    attribute_value text NULL,
    html text NOT NULL
);
```

Найденные элементы сохраняются через Dapper в одной транзакции после успешной обработки запроса.

## Tests

Unit tests do not require Docker or PostgreSQL:

```text
dotnet restore tests/TestTask.Api.Tests/TestTask.Api.Tests.csproj
dotnet build tests/TestTask.Api.Tests/TestTask.Api.Tests.csproj
dotnet test tests/TestTask.Api.Tests/TestTask.Api.Tests.csproj
```

Tests cover validation codes, strict UTF-8/Base64 handling, AngleSharp selectors,
missing attributes, email order including duplicates, AES-256 ECB with no padding,
trailing zero bytes, and response contracts.

Последний подтверждённый результат: 31 passed, 0 failed, 0 skipped.

Email duplicates are intentionally preserved in source order. A missing HTML
attribute is represented by an empty string, while the element is still counted
and its `OuterHtml` is stored.

## Async

Endpoint и service имеют async API. Реальный async используется прежде всего
для I/O: AngleSharp document opening и PostgreSQL operations выполняются async.
CPU/in-memory операции Base64, Regex и AES остаются synchronous; `Task.Run`
для них намеренно не используется.

## Provided test fixtures

Если в корне присутствуют `json_payload_1.txt` и `json_payload_2.txt`, их можно
отправить в API и сохранить фактические responses как `json_result_1.txt` и
`json_result_2.txt`. Эти employer fixture-файлы в текущем checkout отсутствуют;
fake payload/result-файлы не добавляются.

## pgAdmin

pgAdmin доступен по адресу `http://localhost:8080`.

Server registration загружается из `docker/pgadmin/servers.json` на каждом запуске через официальные параметры:

```text
PGADMIN_SERVER_JSON_FILE
PGADMIN_REPLACE_SERVERS_ON_STARTUP=True
```

Сервер использует host `postgres`, port `5432`, database `testtask` и user `testtask`.

PostgreSQL password передаётся через `PGPASS_FILE` и `docker/pgadmin/pgpass`; вручную добавлять PostgreSQL connection и вводить DB password не требуется.

Официальный pgAdmin server mode требует web login. Используются development credentials:

```text
email:    admin@example.com
password: admin
```

Полное отключение web login не включено: документация pgAdmin требует `PGADMIN_DEFAULT_EMAIL` и `PGADMIN_DEFAULT_PASSWORD`, а отключение server mode для web container официально не рекомендуется.

## Validation error codes

Validator намеренно возвращает granular codes:

```text
REQUIRED_SELECTOR
REQUIRED_ATTRIBUTE
REQUIRED_URL_BASE64
REQUIRED_PAGE_BASE64
REQUIRED_KEY_BASE64
REQUIRED_ENCRYPTED_TEXT_BASE64
INVALID_URL_BASE64
INVALID_PAGE_BASE64
INVALID_KEY_BASE64
INVALID_ENCRYPTED_TEXT_BASE64
INVALID_AES_KEY_LENGTH
INVALID_AES_CIPHERTEXT_LENGTH
```

`VALIDATION_ERROR` используется как общий fallback для malformed request/model binding.
